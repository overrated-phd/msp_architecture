Architecture Deep-Dive

MSP Pixel Pipeline Architecture

Detailed block diagrams of every hardware module in the Affine Motion Segmentation Processor — from Cache AG through gradient computation, moment accumulation, region labeling, to inverse matrix and prediction circuits.

Overview

Top-Level Pipeline Architecture

The entire processor forms a single pixel-level pipeline. Data enters at Cache AG, flows through shared preprocessing (gradient → accuracy → weight), then branches into two parallel paths: the model estimation path (gradient moment accumulation → inverse matrix → θ calculation) and the region labeling path (energy calculation → label decision).

Fig. 1 — Top-level architecture. Shared preprocessing (blue) feeds both the model estimation path (green) and region labeling path (orange). Dashed boxes = external memory. Yellow = on-chip tables/buffers.
Fig. — Pixel Pipeline Architecture from the original presentation, showing the block diagram and timing.

What Flows Through the Pipeline

In raster-scan order, each pixel enters as a data packet that grows as it passes through stages. At Cache AG the packet contains the pixel's label and coordinates. After Gradient Calc it gains Ix, Iy, It. After Accuracy & Weight it gains qᵢ and wᵢ. This complete packet then splits — the model path consumes (Ix, Iy, It, wᵢ, x, y) for moment accumulation, while the label path consumes (qᵢ, label, neighbor labels) for energy calculation. Throughput: 1 pixel per clock cycle except at region boundaries (~4-cycle context switch).

Why Multiple RT and MMT Copies?

The processor contains 3 copies of MMT and 2 copies of RT, all holding identical content but accessed by different blocks simultaneously to avoid multi-port memories:

MMT2Moment Calc + Model CalcRead for moment coords; written with new θ after inverse

After Motion Model Calc writes new θ to MMT2, it synchronizes by copying MMT2 → MMT0 and MMT2 → MMT1. After Prediction updates RT1, it copies RT1 → RT0.

External vs Internal Memory

The external memories (dashed boxes) hold frame-sized data: current/next label maps, prediction map, current/next images in off-chip SRAM/DRAM. The internal memories (yellow boxes) hold only region-level or row-level data — RT (128 regions), MMT (128 regions), NIC (25 rows), line buffers (1–2 rows), and Gd accumulators. A key advantage: the proposed architecture does not need internal frame buffers for segmented images — the conventional design required two, but the unified pipeline shares pixel/label reads, eliminating this need entirely.

Block 1

Cache Address Generator (Cache AG)

The Cache AG is the entry point of the pipeline. It reads labels in raster scan order from the external current label map, looks up each region's motion model, computes the warped destination coordinates, and generates read addresses for the next-image cache.

Fig. 2 — Cache AG block diagram. Labels are read in raster order, motion models are looked up from MMT0, destination coordinates are computed, and the NIC returns warped pixel neighborhoods.
Next Image Cache (NIC): Stores 25 rows — the current processing row plus 12 rows above and below — to handle the maximum vertical displacement. The 16 memory banks are arranged so that any 4×4 pixel block can be read simultaneously in one cycle, enabling bilinear interpolation at sub-pixel precision.

NIC Bank Addressing Scheme

The destination coordinates (x+u, y+v) have fractional parts — the pixel rarely lands exactly on an integer grid position. To perform bilinear interpolation, the circuit needs the 4×4 pixel neighborhood around the destination. The NIC's 16 memory banks (each 8 bits × 1K words) are interleaved so that any aligned 4×4 block maps to 16 distinct banks, enabling single-cycle parallel readout regardless of the fractional position. This is critical for maintaining the 1-pixel-per-cycle throughput.

RT Label Correction (Online)

When reading labels from the external current label map, Cache AG also checks the label against RT0. If a region has been invalidated (e.g., merged into another during the previous frame's prediction), the RT stores the corrected label — the surviving region's number. Cache AG replaces the invalid label with the corrected one on-the-fly, without needing to rewrite the prediction map. This online correction saves an entire pass over the prediction map, contributing to the ~40% cycle reduction at the bottom hierarchy level.

Coordinate Computation Precision

The affine displacement is computed in fixed-point arithmetic: x coordinates use 14 bits (10 integer + 4 fractional), y coordinates use 13 bits (9 integer + 4 fractional). The motion model parameters a₁, a₃ (translation) use 16 bits with 8 integer + 8 fractional, while a₂, a₃, a₅, a₆ (rotation/scale) use 1 integer + 15 fractional bits — since these represent small per-pixel rates, they need high fractional precision but little integer range.

Block 2

Gradient Calculation Circuit

Receives the warped pixel neighborhood from Cache AG, performs bilinear interpolation at sub-pixel precision, then computes three luminance gradients:

Fig. 3 — Gradient calculation. The 4×4 neighborhood from NIC is bilinearly interpolated at the sub-pixel destination, then spatial (Ix, Iy) and temporal (It) gradients are computed.

Bilinear Interpolation

The warped position (x+u, y+v) has a fractional component (fx, fy). The sub-pixel intensity is reconstructed from the four nearest integer-position pixels using:

J(x+u, y+v) ≈ (1-fx)(1-fy)·P₀₀ + fx(1-fy)·P₁₀ + (1-fx)fy·P₀₁ + fx·fy·P₁₁ where P₀₀, P₁₀, P₀₁, P₁₁ are the four surrounding pixels from the next image

This interpolation is also applied to the neighboring pixel positions to generate the values needed for spatial gradient computation. The circuit produces interpolated values at the destination and at positions offset by ±1 in x and y.

Spatial Gradient Computation

The spatial gradients Ix and Iy are computed using finite differences of the interpolated next-image pixels. These measure how rapidly brightness changes in the x and y directions at the warped location. The temporal gradient It is the difference between the current-frame pixel I(x,y,t) and the warped next-frame pixel J(x+u, y+v, t+1). All three gradients are quantized to 8-bit signed values, with It clipped to the range [−128, 127] to prevent overflow in downstream multiplications.

Current Image Pixel Source

The current image pixel I(x, y, t) is read from external current image memory in raster scan order — the same order as the label map read. Since both are sequential reads, they can share the same external memory access pattern, simplifying the memory controller and reducing external bandwidth requirements.

Block 3

Motion Accuracy Index & Weight Calculation

Computes the motion accuracy index qᵢ over a 3×3 neighborhood and the binary weight wᵢ. The division in qᵢ is implemented via Newton's method reciprocal with 3 pipelined iterations.

Fig. 4 — Accuracy index and weight calculation. A 3×3 neighborhood (via 2-line buffer) computes qᵢ using Newton's-method reciprocal division, then thresholds to produce binary wᵢ.

Newton's Method Reciprocal (Pipelined)

The division qᵢ = numerator / denominator is computed as numerator × (1/denominator). The reciprocal 1/D is found via Newton's method: starting from an initial guess Y₀, iterate Yₙ₊₁ = Yₙ(2 − D·Yₙ). Three iterations converge to sufficient precision. Each iteration is one pipeline stage, giving a 3-stage pipeline with full throughput.

Fig. 4b — Newton's method reciprocal pipeline. Three stages execute concurrently on three consecutive pixels, maintaining 1-pixel-per-cycle throughput.

The 9σ² Denominator Floor

In textureless areas (flat walls, sky, uniform road), the spatial gradient magnitude |∇I| is very small. Without protection, dividing by a near-zero denominator would produce wildly unreliable qᵢ values. The floor max(Σ|∇I|², 9σ²) ensures the denominator is at least 9σ² — where σ is the assumed noise standard deviation. The factor 9 comes from the 3×3 neighborhood (9 pixels). This means: if the total gradient energy in the neighborhood is less than what noise alone would produce, the circuit treats the measurement as unreliable and clamps the denominator, producing a moderate qᵢ that the threshold can handle gracefully.

3×3 Neighborhood via Line Buffers

Computing qᵢ requires access to the current pixel and its 8 neighbors — the row above, current row, and row below. Since the pipeline processes pixels in raster scan order, the previous row's data must be stored. The WB (Weight Buffer) consists of 2 line buffers (32 bits × 1K words × 2), each storing one row of gradient and DFD products. As each new pixel arrives, its products are written to the buffer and the corresponding values from the two previous rows are read out, forming the complete 3×3 window.

Block 4

Gradient Image Moment Calculation

Accumulates the G matrix (7×7 symmetric, 28 unique elements) and d vector (7 elements) for each region. All 35 elements are computed in parallel for each pixel. The circuit references MMT2 to compute warped coordinates for the moment products.

Fig. 5 — Gradient moment calculation. 35 accumulators run in parallel for each pixel. At region boundaries, G/d are saved to Gd memory and the next region's values are restored (~4 cycle stall).

Context Switching at Region Boundaries

When the raster scan crosses from one region to another, the current region's 35 accumulator values (G matrix + d vector) must be saved to Gd memory and the next region's values restored from Gd memory. This context switch takes approximately 4 clock cycles — the only pipeline stall in normal operation. The Gd memory has 8 banks × 512 words × 32 bits to store all regions' accumulator states.

The 28 Unique G Matrix Elements

G is a 7×7 symmetric matrix, so only the upper triangle (including diagonal) needs to be stored: 7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 unique elements. Each element is a sum of weighted gradient products over all pixels in the region. Examples of what these elements contain:

G[0][0] = Σ wᵢ · Ix² // sum of squared horizontal gradients G[0][1] = Σ wᵢ · x·Ix² // gradient-coordinate cross moment G[0][3] = Σ wᵢ · Ix·Iy // horizontal-vertical gradient cross term G[1][1] = Σ wᵢ · x²·Ix² // can grow very large for big regions d[0] = Σ wᵢ · Ix·(−It) // gradient-temporal product

All 35 accumulators operate in parallel — each pixel contributes to all elements simultaneously. This parallel structure is key to maintaining the 1-pixel-per-cycle throughput.

Overflow Prevention via Adaptive Rounding

Elements like x²·Ix² can grow extremely large when accumulated over many pixels (a 640-pixel-wide region contributes x values up to 640). To prevent overflow within the 32-bit fixed-point accumulators, the circuit applies adaptive rounding based on the region's pixel count. As the accumulator approaches its capacity, less-significant bits are shifted out. This maintains numerical stability without needing wider (and more expensive) accumulators.

Context Switch Flow

When a new label is encountered during raster scan:

1. Current region's G[28] + d[7] → write to Gd memory (35 values saved) 2. New region's G[28] + d[7] ← read from Gd memory (35 values loaded) 3. Resume pixel accumulation for new region (~4 cycles total)

If the next pixel belongs to the same region as the previous (no boundary crossing), the accumulation continues without stall. Region boundaries in typical images represent a small fraction of total pixels, so the average throughput remains close to 1 pixel/cycle.

Block 5

Region Labeling Circuit

The unified boundary update + new region detection circuit. Evaluates the MRF energy function U = U₁+U₂+U₃ for each candidate label and picks the minimum.

Fig. 6 — Region labeling circuit. Boundary check decides BU vs NRD mode. Three energy terms are computed per candidate label, summed, and the minimum-energy label is selected. U₂ correction handles left-neighbor changes on-the-fly.

Boundary vs Interior Decision

For each pixel, the circuit examines the labels of the 4 cardinal neighbors (up, down, left, right) using the Line Buffer (LB) to access the row above. If any neighbor has a different label from the current pixel, it is classified as a boundary pixel → boundary update mode (evaluate candidate labels from adjacent regions). If all neighbors share the same label, it is an interior pixel → new region detection mode (test whether motion fits the current region or should be flagged as "mobile").

Candidate Label Enumeration

For boundary pixels, the candidate labels are the distinct labels found among the neighbors — typically 2, occasionally 3 at triple junctions. Each candidate requires a separate energy evaluation (U₁+U₂+U₃), so the pipeline stalls for the number of candidates minus one. The cycle count analysis assumes an average of 2 candidate labels per boundary pixel. For interior pixels, there are always exactly 2 candidates: "keep current label" (static) vs "assign new region" (mobile).

U₂ Correction Mechanism

The energy term U₂ depends on neighbor labels, including the left neighbor — which may have just been relabeled by this very circuit one cycle earlier. If the left neighbor's label changed in the current pass, the U₂ contribution from that direction must be corrected. The circuit detects this condition and applies an on-the-fly correction to U₂ without needing to re-evaluate the entire neighborhood. This is essential for correct single-pass operation.

Line Buffer for Neighbor Access

The LB stores the labels and accuracy indices from the previous row (8-bit label × 1K words + 16-bit data × 1K words). Combined with the current pixel and a register holding the left neighbor, this provides the full neighborhood context needed for energy computation in a single raster scan pass.

Block 6

Motion Model Calculation

After a complete hierarchy-level image scan, this block computes G⁻¹ via Gauss-Jordan elimination for every active region, then multiplies θ = G⁻¹·d.

Fig. 7 — Motion model calculation. G⁻¹ is computed via Gauss-Jordan (444 cycles/region), then θ = G⁻¹·d (57 cycles/region). The pivot reciprocal is pre-computed in parallel to hide latency.

Gauss-Jordan Inverse Matrix

Unlike the conventional design which computed 7 elements in parallel per column, this circuit uses a pipelined serial approach — computing elements one at a time but streaming them through a pipeline multiplier. Two multipliers in the diagram are actually shared as one physical unit. Numbers are represented in 40-bit floating-point (32-bit mantissa, 8-bit exponent).

Elimination Process

Gauss-Jordan works by processing each of the 7 pivot rows in sequence. For each pivot row k, the circuit: (1) divides the pivot row by the diagonal element G[k][k] (using the pre-computed reciprocal), (2) for every other row i ≠ k, subtracts G[i][k] × (normalized pivot row) from row i. This requires processing all 7 rows × up to 14 elements (the augmented [G|I] matrix). With pipelined multipliers, the 444 cycles per region break down to roughly 63 cycles per pivot, covering the 7×7 augmented matrix operations.

Why Floating-Point?

During accumulation (in Gradient Moment), elements are 32-bit fixed-point because the operations are simple additions and the range is bounded by the image size. But during Gauss-Jordan elimination, intermediate values can span a very wide dynamic range (products and quotients of already-large sums). Fixed-point would require impractically wide datapaths. The 40-bit floating-point format (32b mantissa + 8b exponent) provides sufficient range and precision while keeping the multiplier hardware compact.

Pivot Reciprocal via Newton's Method

Each Gauss-Jordan elimination step requires dividing by the diagonal element (pivot). The reciprocal of the next pivot is computed in parallel with the current elimination step, using Newton's method with 3 iterations. This parallelism hides the reciprocal latency entirely.

Find-First-One (FF1) for Initial Approximation

Newton's method needs a good initial guess to converge in just 3 iterations. The FF1 circuit scans the input integer A to find the position of the most significant '1' bit. This bit position gives the approximate magnitude, from which the initial guess Y₀ ≈ 2^(−MSB_position) is derived. The output is already in floating-point form: the mantissa Y' and exponent p. With this initial approximation, 3 Newton iterations achieve the full precision needed for the 32-bit mantissa.

MMT Synchronization After Model Update

After computing θ = G⁻¹·d for all active regions (57 cycles per region for the matrix-vector multiply), the new motion models are written to MMT2. The circuit then copies the entire MMT2 content to MMT0 and MMT1, ensuring all three copies are synchronized before the next hierarchy-level iteration begins. This copy happens once per hierarchy-level image scan and takes a fixed number of cycles proportional to the number of active regions.

Block 7

Region Prediction Circuit

Runs once per frame after all hierarchy iterations. Warps labels forward using each region's motion model, merges fragmented new regions, counts pixel areas, and deletes tiny regions.

Fig. 8 — Region prediction. Labels are warped forward, fragmented new regions are merged via RT1, pixel counts determine if regions are too small to keep. Results sync to RT0 for the next frame.

Label Warping Process

The circuit reads each pixel's label from the current label map, looks up its region's motion model from MMT1, computes the destination position (x+u, y+v), and writes the label to that position in the prediction map. Processing is in raster scan order, and when two labels map to the same destination (occlusion), the later-written label wins — effectively giving priority to the foreground. Positions that receive no label become uncovered areas and are initialized with a special "uncover" label.

Region Merging Logic

During new region detection (Step 3 of the algorithm), a single physical object may be split into multiple new regions if it spans non-adjacent pixel clusters. During prediction, as the raster scan progresses, the circuit detects when two new regions that share the same parent region have become spatially adjacent. When this happens, it merges them by: (1) marking the smaller region as invalid in RT1, (2) setting the smaller region's "corrected label" field to point to the larger region's label. All future references to the invalid label will be redirected to the survivor.

Pixel Counting and Cleanup

Simultaneously with merging, the circuit counts the number of pixels in each region and writes these counts to RT1. After the prediction scan completes, a post-processing pass through RT1 performs cleanup: (1) merged regions have their pixel counts combined, (2) regions whose pixel count falls below a minimum threshold are deleted (marked invalid). This prevents the system from being cluttered with tiny noise regions.

Prediction Map Rewrite Optimization

Normally, after RT cleanup changes some labels (merging/deleting), the prediction map should be rewritten with the corrected labels. This would require an additional full-image pass. The proposed design eliminates this pass by performing online label correction in Cache AG: when the next frame reads from the prediction map (which becomes the "current label map"), Cache AG checks each label against RT0 and substitutes corrected labels on the fly. This optimization, combined with using the 1st-iteration motion model for prediction instead of waiting for the 2nd, saves approximately 40% of bottom-hierarchy-level cycles.

Where Do the Cycles Go?

The vast majority of cycles are spent in the pixel-scanning pipeline (gradient through labeling). For level 0 at full VGA resolution: 640 × 480 = 307,200 pixels per scan, and with 2 iterations that's ~614,400 pixel cycles. The remaining cycles come from: region boundary context switches (~4 cycles × number of boundaries), motion model calculation (444 + 57 cycles × 32 regions = ~16,000 cycles per iteration), and pipeline latency (22 cycles per scan startup).

Comparison with Conventional

Conventional: 167 MHz required for VGA 30 fps. Proposed: 62 MHz for VGA 60 fps. At the same clock frequency, the proposed design achieves >5× throughput. This comes from: (1) eliminating redundant gradient/accuracy computations, (2) unifying boundary update and new region detection, (3) removing the need for full-frame internal buffers, and (4) the ~40% cycle reduction from prediction optimizations.
